# Android 0.1.11 build 12 Stable release

Date: 2026-09-25. Source checkpoint: the media/navigation change set on
`main`; the web commit was still local when the APK was published. This is
LETSCUBE's first-party APK catalog, not a Google Play submission.

## Release proof

- `android:build:production:release` produced a signed APK and AAB from the
  protected local signing inputs and production embedded web bundle. Neither
  secrets nor signing material entered Git or this report.
- The local and independently downloaded public APK both passed
  `android:verify:release` (package, 0.1.11/build 12, Firebase init resources,
  permissions, exported components and App Links). Their byte counts and
  SHA-256 match: **7,534,407 bytes**, SHA-256
  `9242a541b93833811bc76547eece69d64c1e3c820765de7a454352ec2b7a941f`.
  The signer certificate digest matches the published 0.1.10 APK.
- An isolated Android 14 AVD installed the signed build and rendered the guest
  login screen. The designated Realme upgraded 0.1.10 to 0.1.11 in place and
  launched the activity; no personal conversation was inspected. The final
  signed APK was reinstalled on both after the last UI changes.
- The Android MediaStore instrumentation suite passed 2/2 on the isolated AVD:
  gallery path/bytes/published state and failed-transfer cleanup. Android debug
  unit tests, full JS unit suite, typecheck, web production build and focused
  Playwright desktop/mobile visual tests passed. The final focused browser run
  was 59 passed, 1 width-conditional skip; later targeted checks covered the
  final menu wording and retry-arrow placement. The separate iPhone PWA owner
  reported synthetic WebKit profile/share checks 8/8, not physical-iPhone QA.
- Before publication, the old Stable manifest was copied byte-identically to
  `/srv/letscube/backups/android-stable-pre-0.1.11-build12-20260925/stable.json`
  (SHA-256 `9c514d85e8076598ec26501a3899d83a4a056892f0fa76072e5452f748c3dc7a`).
  The server-side upload matched the local APK before the publish script ran.

## Limits and rollback

The gallery bridge is proven by AVD instrumentation, not by authenticated
in-chat saving on a physical device. AVD launch and Realme in-place upgrade do
not prove delivery timing on an official-GMS phone. There is no explicit
app-private media cache, transfer progress or cancellation; see the
[audit](2026-09-25-media-navigation-audit.md).

Rollback: confirm the backup manifest and immutable 0.1.10 APK, then restore
the Stable manifest atomically under the release-catalog publish lock. Do not
overwrite either versioned APK. Web rollback is a separate Coolify operation.
