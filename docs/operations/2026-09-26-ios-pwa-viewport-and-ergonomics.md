# iPhone Home Screen PWA: viewport and chat ergonomics (2026-09-26)

Owner: the separate iOS/MacOS chat. Stage: source and synthetic-browser QA complete; live web deployment and physical iPhone acceptance are separate gates. Source: tester screenshots of the installed iPhone 15 Pro Max PWA and Telegram, plus the existing D-111 viewport implementation and tests. Do not copy private chat content into this record.

The installed shell previously replaced its `100vh` height with `visualViewport.height` even while the keyboard was closed. In the WebKit fixture, a 932 px standalone viewport with a 872 px visual viewport then rendered a 872 px shell and left a 60 px lower band. The new rule retains `100vh` at rest and fits to the measured visual viewport only while the keyboard is detected. The safe-area padding and keyboard pan remain in force. This branch is only for `data-ios-standalone`; a Safari tab keeps `100dvh` and its existing keyboard lift.

The same scoped pass raises the installed iPhone chat header title to 17 px, list title/preview to 16/14 px, and primary chat/composer touch targets to 48 px. The message body remains the previously agreed 16 px default, with the user's text-size setting honored. Liquid Glass surfaces and other platform layouts are unchanged.

Verification: the short-viewport case failed before the runtime change at 872 vs 932 px and passed afterward. The final installed-viewport matrix passed 24/24 in WebKit and Chromium, including Safari-like browser mode, keyboard open/dismissed, chat/list/public shells, and a 320 px narrow screen. Safe-area portrait/landscape cases passed; a pre-existing ambiguous test locator was narrowed and its self-check passed on rerun. Relevant 20 unit checks, web typecheck, and a fixture-configured production build passed. Synthetic light/dark renders were inspected without using production chat data.

Remaining gate: Windows WebKit emulation cannot prove iOS Home Screen chrome or a physical keyboard.
