# Task1: D-356, задержанный ответ чтения колокольчика

**Контрольная точка, 2026-11-05.** Владелец: Codex, Task1. Этап: локальная
браузерная приёмка одного сценария на синтетическом backend. Код продукта,
Task9, общие документы и production не менялись.

## Сценарий

1. [Тест](../../tests/e2e/d356-notification-held-read.spec.ts) переиспользует
   `messageActionsFixture` и `RealtimeFixture`. SID1 восстанавливается через
   SDK `setSession`. Первый чат, сообщение и уведомление принадлежат только
   фикстуре. Реальный Bell отправляет точный групповой RPC
   `notifications_mark_chat_messages_read` с SID1 и пустым горизонтом.
   Фикстура отмечает свою строку прочитанной, но удерживает её HTTP ACK.
2. Реальные меню, подтверждение выхода и LoginForm запускают SDK Auth.
   Принимается только точный `scope=local` SID1, затем один password grant
   тому же UID с SID2. Документ не меняется; store и Auth-события не подменяются.
   Наблюдаются новая подписка feed v2 с SID2 и точный RPC чтения с его bearer.
   Клик по второму уведомлению даёт точный URL сообщения и одно событие прыжка.
3. Старый ACK освобождается только после положительного контроля. Старый
   запрос получает `requestfinished`, а не abort. За 400 мс нет нового
   запроса с SID1 или проверки доступа к старому чату; URL и список прыжков
   не меняются, ошибок страницы нет.

## Красный и зелёный

- **RED:** временный Vite transform только в памяти заменяет один
  `const canCommit = beginNotificationAction(entry.latest.user_id);` на
  `const canCommit = () => true;`. Точка заменена ровно один раз. При том же
  успешном переходе SID1 → SID2 после старого ACK появляется
  `old access lookup`, и тест падает на буквальном нулевом ожидании.
- **GREEN:** неизменённый код, Chromium desktop 1440, 2/2 последовательных
  прогона после RED, без retries. Никакой продуктовый патч не потребовался.
- Синтетический `route.fulfill(204)` в этом стенде дал `net::ERR_ABORTED` и
  корректный отказ выхода. Фикстура отвечает JSON 200 на тот же точный
  запрос, чтобы проверить успешный SDK logout. Это не проверка живого HTTP 204.
- `KUB_QA_ALLOW_MUTATIONS=0`, снимки/трассы/видео отключены. HTTP и WebSocket
  за пределами изолированного стенда заблокированы; контексты, сервер и
  временные артефакты удалены. Данных и сессий на сервере не создавалось.

## Граница приёмки

Закрыта локальная проверка одного группового Bell read ACK через обычный
logout/login. Открыты живой серверный Bell read при смене SID, отозванное
приглашение, живые заменённые и ручные переходы и отдельный settings read.
[Локальный ручной возврат](2026-11-05-task1-d356-manual-jump.md) и ранее
принятый живой held-access не повторялись. Нативной или релизной приёмки нет.
