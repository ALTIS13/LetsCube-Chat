# Task1: D-356, ручной возврат в чат

**Контрольная точка, 2026-11-05.** Владелец: Codex, ограниченная проверка Task1.
Этап: локальное исправление и браузерная приёмка одного сценария. База:
`main` / `32ab32fc`, с сохранением параллельных изменений. Не опубликовано.

## Воспроизведение и исправление

1. Реальный колокольчик открывает уведомление в чате A по адресу
   `/chat/A/m/M` и планирует прыжок на 150 мс. Положительный контроль без
   вмешательства даёт ровно одно событие для пары A/M.
2. Во втором проходе до срабатывания таймера пользователь кликает в списке
   чат B, затем чат A. Оба перехода проверяются по URL; итоговый
   `/chat/A` не содержит адреса сообщения.
3. **RED, неизменённый Bell:** после 200 мс появляется второе событие A/M,
   несмотря на сохранение ручного адреса. Контрольный прыжок и оба ручных
   перехода дошли до своих проверок. 200 мс меньше первого 250-мс прыжка
   `useChatAddress`.
4. **GREEN:** `NotificationBell` запоминает любое изменение выбранного чата
   между постановкой и исполнением таймера. Возврат к тому же ID не оживляет
   старое действие. Подписка снимается при исполнении таймера, даже если
   действие уже отозвано. Ручной адрес остаётся, нового прыжка нет, положительный
   контроль по-прежнему проходит. RPC чтения, права и маршруты не изменены.

## Проверки

- [Браузерный сценарий](../../tests/e2e/d356-notification-manual-jump.spec.ts):
  Chromium desktop 1440, исходный RED 1/1 по лишнему событию, после исправления
  GREEN 1/1. Реальные SDK, компонент, store и маршрутизация; Auth, REST и
  Realtime feed v2 обслуживаются существующими синтетическими фикстурами.
  Два точных запроса чтения Bell и одна пара chat/message в положительном
  контроле проверены отдельно.
- [Компонентный стенд](../../tests/unit/notify-click-owner-lifetime.test.mjs):
  67/67, включая 19 компилируемых мутаций. Мутация возврата старой проверки
  по текущему ID отклонена по наблюдаемому лишнему прыжку после A → B → A.
  Фикстура обновлена с legacy GET до feed v2; она различает сверку ACK самим
  hook и отдельный refresh обработчика Bell. Это не новая живая приёмка invite.
- `pnpm.cmd --filter @workspace/kub run typecheck` и проверка diff прошли.
- `KUB_QA_ALLOW_MUTATIONS=0`. Vite слушал только loopback; нет обращений к
  production, реальных пользователей, снимков, трасс или видео. Контексты
  закрыты; временные кэш Vite, каталог теста и проверенная по SHA-512 копия
  esbuild из локального кэша удалены. Нет данных на сервере для удаления.

## Что остаётся

A → B → A. Проверка замены действия осталась зелёной на компонентном стенде,
но живая приёмка заменённого действия и ручного перехода не выполнялась.

UID, отозванное приглашение и остальные не покрытые живые действия D-356
(в том числе settings read). Ранее принятый
[held-access](2026-10-18-production-completion.md#d356-actual-held-access-across-ui-reauthentication)
не повторялся. Нативные платформы, WNS и Topic rollout не проверялись.
