# Android 0.1.10 build 11 Stable release

Date: 2026-09-25. Android media-export source: `4fc1b02c`. Version bump:
`575c64f8` on `main`. This is the first-party APK catalog release; the AAB
was built locally but not submitted to Google Play.

## Evidence

- The existing ignored `.ops-private/android-signing` inputs passed the release
  identity check. No key or password was printed, committed or uploaded. The
  published 0.1.9 APK matched its Stable SHA-256; its certificate digest matched
  the new signed APK.
- `android:build:production:release` produced a non-debuggable signed APK/AAB
  with the production embedded web bundle. `android:verify:release` passed for
  the local APK and the independently downloaded public APK, including package,
  version, Firebase initialization resources, exported components, permissions
  and App Links association.
- The 0.1.10 APK upgraded 0.1.9 in place on the designated Realme test phone;
  package metadata reported build 11 and `MainActivity` launched. The device
  had its notification shade open, so authenticated UI and push were not tested.
  A separate Android 14 AVD installed the signed APK and visibly rendered the
  guest login screen. Earlier debug-APK QA verified native media export through
  the system picker with byte-identical saved content and cleanup.
- Release catalog tests: 43 passed, 1 baseline skip. Focused media-action
  tests, Android debug unit suite, typecheck and 18/18 media-viewer browser
  cases passed before the version-only bump.
- Before publication, the previous Stable manifest was copied byte-identically
  to `/srv/letscube/backups/android-stable-pre-0.1.10-build11-20260925/stable.json`.
  The uploaded APK SHA-256 matched the local artifact. The public Stable
  manifest and independently downloaded APK match version 0.1.10/build 11.

## Limits and rollback

The signed release has not had authenticated FCM or in-chat media export
exercised on a physical official-GMS phone. Source/AVD proof is not that
device proof. Windows Stable remains 0.2.14/build 18 and loads live web;
iPhone PWA belongs to the separate `iOS/MacOs` owner.

Rollback: confirm the backup manifest and immutable 0.1.9 artifact, then
restore the manifest atomically under the release-catalog publish lock. Do
not overwrite either versioned APK. Rolling back the web container is separate.
