## Test-Only SQL Prototypes

and [source tests](../../tests/server/media-variant-avatar-publication.test.mjs)

the repository's captured bootstrap. This is **not an installable migration**, a
full deployed-schema test or a worker wired to a new production RPC.

One SQL call locks the owner, compares its current URL, and performs DELETE/INSERT
in a transaction. Both stale ready and stale failed publications are refused;
current successful/failed replacements and unrelated-row preservation pass.
An injected real insert exception rolls back the preceding DELETE. Anonymous and
authenticated roles cannot call the trusted fixture publisher or read its tables;
RLS stays enabled. These are fixture privileges, not a production policy audit.

Actual independent SQL sessions establish the owner row lock by exact
`pg_blocking_pids` relationships, not sleeps: the publisher waits at a test-only
insert barrier, and the owner setter waits for that publisher. Removing the
installed owner lock lets the setter commit before publication; the literal
waiting oracle goes RED. Removing the installed URL predicate permits stale A;
the unchanged literal false oracle goes RED. Original definitions are restored
in `finally`. Exact owned database directories are checked absent after disposal.

## Next Bounded Contract

The measured gaps rule out a client-only reload or a token-only lifecycle fix.
Continue source-only, without replaying accepted production SQL:

1. Retain a distinct logical source epoch on every avatar change/clear, including
   A -> B -> A, and bind claimed work to it. Cover profile/chat and bot/trusted/
   legacy setters; scan fallback also needs an epoch, not only a queue token.
2. Give new variant attempts separate target addresses so a late A cannot
   overwrite B. A source-path hash is address separation only; it is not a
   bytes/version hash or provider terminality. Preserve old addresses and held
   rows until their own lifecycle contract permits otherwise.
3. Record durable source AND target intents before external GET/PUT; retain
   pending/unknown/accepted-but-unpublished outcomes through crash/retry. No SQL
   transaction spans network I/O. Current failed/stale rows are also holders.
4. Publish ready/failure outcomes atomically under current epoch and target
   binding. Finish/retry only the exact owned queue claim; do not discard newer
   work. Test publication after setter changes and setter waits after admission.
5. Integrate actual worker RPCs and all setters in disposable fixtures before a
   full PG17/PostgREST transfer. Only then begin separately owned deployed-
   equivalent Storage capability/physical-generation proof.
