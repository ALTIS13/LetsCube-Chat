# Android 0.1.9 build 10 Stable release

Date: 2026-09-24. Source commit: `fdbb6d72bb57e538701b8de929f0779aa8e4bc38` on `main`.
The owner explicitly authorized Stable publication. This is an APK catalog
release, not a Play Store or AAB submission.

## Result and evidence

- `pnpm.cmd typecheck`: exit 0. The full `tests/unit` Node suite: exit 0.
- Focused chat privacy, history and list-scroll Playwright suite on desktop
  1440px and mobile 390px: 32 passed, 6 intended platform skips, exit 0.
  The last older-page retry case additionally passed three consecutive runs
  per viewport. The mobile chat-list anchor measured 0px drift in both themes.
- Local ignored Firebase client configuration and signing inputs were present.
  `android:build:production:release` rebuilt the embedded production web
  bundle and produced a signed APK and a local AAB. Neither private input was
  printed or committed. The AAB was not published.
- `android:verify:release` passed on both the local and publicly downloaded
  APK. This includes package/version/signing, Firebase initialization resources,
  permissions and App Links association. The previous public 0.1.8 APK hash
  matched its manifest, and its signing certificate matched the new APK.
- The signed APK installed on an isolated, read-only Google Play Android 14
  AVD, reported 0.1.9/build 10, focused `MainActivity`, and rendered a usable
  guest login screen. The screenshot was inspected locally, not committed.
- The designated Realme Android 15/microG test handset had a differently signed
  0.1.8 build. The owner had authorized changes to this test phone; only
  `com.kub.messenger` was removed and the signed 0.1.9 installed. Package
  metadata confirms build 10. Its screen remained locked, so no authenticated
  UI or live push claim is made from this device.
- GitHub `main` and the healthy production web container both reached the
  exact source commit. The public web page returned HTTP 200 and a fetched
  bundle contained the new chat-history error copy.
- The previous Android Stable manifest was copied byte-identically to
  `/srv/letscube/backups/android-stable-pre-0.1.9-build10-20260924/stable.json`
  before publication. The uploaded APK hash and publisher syntax were checked.
  Public Stable now reports 0.1.9/build 10, three highlights and
  `mandatory=false`.

## Limits and rollback

The owner's earlier official-GMS observation was on signed 0.1.8/build 9,
not this candidate. This pass did not establish signed 0.1.9 authenticated
FCM delivery, physical official-GMS display latency, audible sound, or a
long-session/device matrix. The new `messages_v2` OS sound applies only to
fresh installations; upgrades retain their existing channel settings.

Windows Stable remains native 0.2.14/build 18. It loads the updated live web
UI, but `windows:tauri:signing:preflight` failed because
`WINDOWS_SIGNING_PROVIDER` is absent. No unsigned Windows installer was
published. iOS/PWA is owned by a separate agent and was not changed here.

Rollback: verify the backup manifest above and the immutable 0.1.8 APK,
then restore the manifest atomically under the release-catalog publish lock.
Do not overwrite either versioned APK. A web rollback is independent and
must be measured against its running container image and public bundle.
